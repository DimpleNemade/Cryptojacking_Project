# Security Policy

## Reporting a vulnerability

This project uses **GitHub private vulnerability reporting** (advisories). Do not
open a public issue for security-sensitive defects.

1. Go to the repository **Security** tab → **Report a vulnerability**.
2. Provide a clear description, affected version, reproduction steps, and impact.
3. Maintainers will acknowledge within a reasonable timeframe and coordinate a fix
   and disclosure window.

If private reporting is unavailable, contact the maintainer through a GitHub
security advisory draft. Do **not** email unsolicited attachments or live evidence.

## Scope

This tool is an offline, evidence-aware triage CLI for cryptojacking indicators.
Out of scope for this policy:
- Live malware, miner binaries, or evidence samples (do not send them).
- Hosted services, endpoints, or cloud infrastructure (none are operated).

## Safe handling expectations

Contributors and users must not upload to issues or PRs:
- Malware or miner binaries.
- Credentials or secrets.
- Personal data or live evidence.
- Confidential reports or unredacted paths/logs.

## Supported versions

Only the latest alpha/prerelease line is supported during the alpha phase.
Security fixes are applied to the default branch.
